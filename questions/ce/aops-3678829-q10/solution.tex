Start with one cluster per input point, storing its member indices, size and coordinate sum. While more than $k$ clusters remain: compute each centre as sum divided by size; examine every pair of centres; select a closest pair, using a fixed tie rule; replace that pair by the union, adding their sizes and coordinate sums. Return the remaining member sets. This implements precisely the stated centroid algorithm. It need not reproduce meaningful external categories: nonconvex groups, differing scales, outliers and equal-distance ambiguities can all make geometric proximity disagree with the intended labels. The mathematical procedure still returns a partition.
