\textbf{(a)} If the rule is correct for the $d$-th of a month with code $m$, then the $d$-th of the next month comes $L$ days later, where $L$ is the length of the first month, so its weekday is $m+L+d+y$; the next month's code must therefore be $m+L\pmod7$. With $31\equiv3$, $30\equiv2$ and $28\equiv0\pmod7$:
\[
\begin{aligned}
&\text{Feb}=6+31\equiv2,\quad \text{Mar}=2+28\equiv2,\quad \text{Apr}=2+31\equiv5,\quad \text{May}=5+30\equiv0,\\
&\text{Jun}=0+31\equiv3,\quad \text{Jul}=3+30\equiv5,\quad \text{Aug}=5+31\equiv1,\quad \text{Sep}=1+31\equiv4,\\
&\text{Oct}=4+30\equiv6,\quad \text{Nov}=6+31\equiv2,\quad \text{Dec}=2+30\equiv4,
\end{aligned}
\]
all as in the table. (The step from February to March uses a $28$-day February, so the table is built for a common year.)

\textbf{(b)} Take a date from March to December in year $Y$. The same date in year $Y+1$ is $365$ days later, or $366$ days later if the February $29$ in between exists, i.e.\ if $Y+1$ is a leap year. Since $365=52\cdot7+1$, the weekday moves on by $1$, or by $2$ if $Y+1$ is a leap year, and the year code must do the same. In the table: $2003\to2004$ is $3\to5$, $2007\to2008$ is $1\to3$, $2027\to2028$ is $5\to0$, and so on.

\textbf{(c)} The rule gives $6+1+0=7\equiv0$, a Sunday, but January $1$, $2000$ was a Saturday. By (b) the year codes are fitted to dates from March onwards (for $2000$: March $1$, $2000$ gives $2+1+0=3$, a Wednesday, which is right). In a leap year February has $29$ days, so January and February dates lie one more day before March than in a common year, and the rule is one day too late for them. \textbf{Correction:} in a leap year ($2000$, $2004$, $\dots$, $2028$), subtract $1$ for dates in January and February. Then January $1$, $2000$ gives $6+1+0-1=6$, a $\boxed{\text{Saturday}}$, as it should. With this correction the rule is right for every date from $2000$ to $2031$.
